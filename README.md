# 加班记录

手机 / 电脑均可使用的加班与调休记录网页。本机优先保存，可选择连接 Cloudflare D1 云端同步；无需账号，使用一份随机同步码连接自己的多台设备。

正式网站：<https://jiaban-x2m.pages.dev> · 源码仓库：<https://github.com/ypipiaA/jiaban>

支持上班与加班分别记录、完整月报、多设备同步和离线使用。第一次使用同步时，在一台设备上创建空间，再把同步码输入另一台设备即可。

## 手机安装

安装入口：<https://jiaban-x2m.pages.dev/install.html>。安卓可下载 APK，苹果在 Safari 中选择「分享 → 添加到主屏幕」。App 与网页使用各自的本机存储，安装后用原同步码连接即可接回已有记录。安卓工程、构建方式与签名保管说明见 [mobile/README.md](mobile/README.md)。

当前版本 **1.3.1**，版本号显示在设置页底部。多设备同步默认折叠，收起时仍显示同步状态并继续自动同步。安卓 1.3.0 及以上可在 App 内检查和下载新版；苹果桌面版联网获取更新。

## 源码仓库

仓库包含网页、云端同步接口、安卓工程、构建与发布脚本及测试。Cloudflare 令牌、安卓签名密钥、数据库、日志、本机配置和安装包不提交到 Git。

克隆后可按下方说明运行网页开发服务。安卓 APK 请从安装入口下载；正式发布前，将需保留的版本安装包按原文件名放回 `public/downloads/`，并用已有 `.apk.sha256` 文件核对完整性。构建安卓升级包前须恢复原签名材料；沿用原站点发布还需在本机配置 `.cf_env`。不要把这些凭据或签名文件加入仓库。

## 月报

- 月报顶部只显示总工时、加班、出勤；表格仅显示已记录日期，最新在前，每页 5 条。
- 表格显示日期、星期、类型、上班、加班、合计、换调休、用调休和备注 9 列。电脑宽屏可直接查看全部字段；手机在表格内左右滑动，日期固定在左侧，整页不横向移动。
- 点日期修改；空备注列缩窄，当前页有备注时加宽并完整换行显示。每页 5 条，整月合计始终统计全部记录。空月份只显示「去记一笔」，不列出空日期。
- 调休余额直接可见，点「明细」展开流水和其他统计。流水也分页，每页 5 条。
- CSV 导出包含整月和合计，可用 Excel 打开；文字中的公式前缀会作文本转义。
- 日期卡片直接填写上班和加班两个时数并保存，例如上班 8 小时、加班 2 小时，合计 10 小时。调休和备注可打开编辑面板填写，有旧备注时自动展开。
- 「本月总工时」与其他统计卡片统一白底；总工时包含上班和加班，卡片中分别展示合计与加班时数。
- 工时设置、备份管理和同步恢复工具默认收起，点击对应项目可展开。
- 限制页面手势、Ctrl / Command 加减键及滚轮缩放，保留普通滚动和输入；浏览器菜单和操作系统的缩放设置仍由设备控制。
- 日期卡片清楚显示「待保存 / 已保存」，修改已有记录后按钮显示「保存修改」。聚焦数字输入框时，滚轮不会意外改变时数；点击当前导航不会重置正在填写的内容。
- 工时设置尚未保存时，离开页面会提示；其他窗口保存也不会覆盖设置草稿。长备注在表格内完整显示，翻页回到表格顶部并保留当前横向位置，切换月份回到日期列。

## 两台设备连接

1. 在**已部署的同一个 HTTPS 网站**上打开「设置 → 多设备同步」，第一台点击「开启同步」。
2. 等待显示「已同步」，点击「连接另一台设备」复制同步码。
3. 第二台设备打开同一网站，展开「已有同步码？连接另一台设备」，粘贴同步码并连接。
4. 两台设备各自保留本机数据；保存后自动同步，页面在前台时每 60 秒检查一次，回到页面或恢复网络时也会检查，可点击「立即同步」。

同步码是随机生成的访问密钥，请只交给自己的设备，并另存一份。**丢失所有设备上的同步码后无法通过姓名或手机号找回云端空间。** 同步码不放在网址、普通 JSON 备份或服务端数据表里；服务端仅保存其 SHA-256 标识。本机连接配置中保存同步码，云端通过 HTTPS 传输。

### 合并与恢复

- 不同日期和独立的余额调整自动合并，设置按字段合并。
- 同一天的不同修改、删除与修改冲突会暂停同步，在设置页逐项选择，不会静默覆盖。
- 请求期间继续录入的本机修改会保留，下一轮继续核对。
- 上传期间连续修改同一天，不会把自己刚上传的旧值误报为另一设备的修改；刷新后也会继续补传。真正来自另一设备的同日修改仍需确认。
- 日期卡片或编辑面板正在填写时，云端数据暂缓应用；保存后自动继续同步，避免覆盖尚未保存的输入。切换日期、月份或页面前也会提示保留未保存内容。
- 接收云端修改前保留最近 **3 份本机恢复副本**；每次云端更新保留旧版，最多 **30 个历史版本**。均可在设置中下载 JSON，再经「导入备份」恢复。「云端历史」和「本机恢复副本」再次点击可收起，长列表在面板内滚动。
- 「断开此设备」保留本机和云端数据；必须先断开同步才能清空本机，避免把一次清空传播到所有设备。
- 导入备份会提示覆盖，并提醒已连接的设备会同步这些修改。
- 同步不是无限期历史备份；仍建议定期导出 JSON 到独立位置。单个同步空间当前最多 256 KB 数据。

## 工时规则

- 上班与加班独立填写，工作日、周末均不自动生成加班；两项合计不超过 24 小时，支持只填加班（上班为 0）。
- 标准工时只用于新记录的默认上班时数和调休折算，已有记录保持原值。
- 保持旧备份和云端格式：`hours` 仍为上班加加班的总时数，`ot` 为其中的加班部分。旧记录编辑时拆开显示，总工时、调休余额和备注保持不变。
- 调休余额按全部记录和手动调整累计，包含提前录入的日期。
- 支持旧版上下班时间备份；损坏的本机记录不自动覆盖，可导出原始内容。
- 旧备份中的零小时调休仍可查看，但不计入调休天数。

## 本地预览与开发

需要 Python 3.10+ 执行同步 / 部署脚本，Node.js 22.13+（推荐 24）运行带数据库的本地服务。

```powershell
git clone https://github.com/ypipiaA/jiaban.git
cd jiaban
npm install
python sync_public.py
npm start
```

打开 <http://127.0.0.1:8765>。本地服务运行相同的 Worker 接口，使用 `.local/sync.sqlite` 持久保存开发数据。仅暴露 `public/` 中允许访问的应用文件。**本地服务的数据与正式网站独立；手机不能通过电脑的 localhost 地址访问。跨设备正式使用请完成下面的云端部署。**

仅检查静态网页时，也可以运行 `python -m http.server 8765 --bind 127.0.0.1 --directory public`，此方式不提供同步接口。直接打开根目录 HTML 时，需保留同目录的 `sync-core.js`、`sync-client.js` 和 `app-update.js`；只支持本机记录，不支持云同步和 PWA 安装。

## Cloudflare 配置与发布

项目沿用现有 Cloudflare Pages。凭据保存在根目录 `.cf_env`，文件已忽略，不要放进 `public/`：

```text
CF_TOKEN=你的令牌
CF_ACC=你的账户标识
```

令牌需要针对现有站点所属账户的 **Cloudflare Pages 编辑** 和 **D1 编辑** 权限。

```powershell
python cloud_setup.py           # 只读检查站点与数据库权限
python cloud_setup.py --apply   # 创建 / 复用 jiaban-sync，初始化表并绑定生产及预览环境
python cf_deploy.py             # 自动构建 public/ 并部署
```

`deploy.bat` 先只读检查现有站点与数据库，再部署，任何一步失败都会停止。可设置 `JIABAN_PYTHON` 指向本机 Python。配置脚本保留已有数据库绑定，遇到同名 `DB` 指向其他数据库会停止，不覆盖。显式执行数据库初始化时仅创建不存在的表。

本项目的发布脚本只接受 `jiaban / jiaban-x2m.pages.dev`，发布前核对首页身份、文件清单和同步 Worker，拒绝混入其他应用文件；发布后逐字节比对正式首页，并检查同步接口确实返回 JSON 就绪状态。其他程序应使用各自的 Cloudflare 项目，不能复用此站点作为发布目标。

日常双击 `deploy.bat`：先只读核查配置，再发布。只有首次初始化或明确修复数据库配置时才单独执行 `cloud_setup.py --apply`；配置脚本同样会核对项目和域名，拒绝环境变量把目标改到另一个程序。

部署后 `/api/health` 应返回 `{"ready":true,"version":1}`。正式域名沿用现有 Pages 项目。首次访问会缓存应用外壳，离线可继续记录；`/api/` 不进入离线缓存。

静态页面或脚本临时返回 503 等错误时，若已有可用缓存会自动打开本机版本，仍可录入；同步接口继续显示真实连接状态，恢复服务后再补同步。

## 文件

- `加班记录.html`：页面、记录管理和月报。
- `sync-core.js`：浏览器 / Worker 共用校验和三方合并。
- `sync-client.js`：连接、同步、冲突确认和恢复副本。
- `app-update.js`：安卓应用内更新界面、苹果桌面版更新提示和当前版本展示。
- `sync-worker.mjs`、`schema.sql`：云端接口与 D1 表结构。
- `sync_public.py`：生成 `public/index.html`、复制客户端脚本、打包 `_worker.js`、刷新离线缓存版本。修改源文件后必须重新运行。
- `dev-server.cjs`：本地 SQLite 服务，不依赖第三方服务端库。
- `mobile/`：安卓工程、原生更新与备份桥接、签名构建脚本及依赖锁定文件。
- `android_release.py`：安装包版本与校验值核对、更新清单生成与发布准备。
- `tests/`：页面、离线使用、多设备同步、更新流程和部署保护检查。

## 验证

```powershell
npm install
npx playwright install chromium
npm test
python -m unittest discover -s tests -p "test_*.py"
```

测试使用临时数据库和隔离的浏览器环境，覆盖两台独立设备、离线合并、冲突选择、历史版本、请求期间编辑、月报表格 / CSV、原有录入与离线功能。截图位于 `test-results/`。只有线上端到端验证通过后，才能认为真实跨设备服务已可用。

线上验收脚本为 `tests/verify-live.cjs`（需手动执行，不包含在 `npm test` 中）。它创建带随机标记的独立测试空间，检查配对、双向离线合并、冲突恢复、云端历史下载和离线重启。验收后执行 `python tests/cleanup_live.py`，仅清理该测试空间；不要将 `.local/` 中的临时连接配置分享或发布。验收结果保存于 `test-results/live-verification-result.json`。
